# 컴퓨터 보안 - 컴퓨터는 어떻게 데미터를 안전하게 지키는가

보안의 핵심은 우리와 우리의 물건을 우리가 정의한 안전함에 따라 유지하는 것이다.

## 보안과 프라이버시 개요

### 위협 모델

* 위협 모델

시스템이 직면할 수 있는 잠재적인 보안 위협을 식별하고 분석하는 과정을 말한다.

위협 모델을 정의하지 않으면 효과적으로 보안을 강화할 수 없다는 것이다. 위협과 위협 에 대비한 방어 사이에 균형을 맞춰야 한다.

### 신뢰

제어할 수 없는 대상을 신뢰할 때마다 보안은 감소한다. 

보안을 아주 높이기 위해서는 꼭 필요한 대상만으로 신뢰를 최소화해야 한다.

* 신뢰 위반의 사례

1. 의도적 : 고의로 시스템이나 보안을 침해하는 악의적 행위
2. 무능 : 실수나 역량 부족으로 인해 발생하는 신뢰 위반
3. 부정직 : 고의적인 기만과 거짓말로 보안을 무력화하는 행위

* 수천 개의 눈 원리

공유와 협업을 통해 보안을 강화하는 의미

### 물리적 보안

* 공격 표면 :  시스템에 침입하거나 손상을 줄 수 있는 모든 취약점과 진입 지점의 총합

* 권한을 부여 : 비밀번호 등을 통해서 사용할 수 있는 권리가 주어진다 -> 인가

* 백도어 : 편의상 만들어진 취약점

### 통신 보안

1. 인증 : 상대를 식별
2. 진본성 : 통신이 변조되지 않았음을 증명
3. 중간자 공격 : 당사자의 중간에 공격자가 들어가서 통신을 가로채거나 변경하는 상황
4. 크립토그래피 : 메시지를 받을 수신자만 아는 비밀 코드를 사용해 암호화하고, 수신자는 이것을 복호화


### 모던 타임즈

요청을 과도하게 보내 정당한 고객들이 서비스를 받지 못하게 방해하는 것을 dos라고 한다.

최근에는 이런 식의 공격은 대부분 분산 서비스 거부 공격으로 이루어진다.

이런 공격은 '프록시'를 사용하기 때문에 추적이 어렵다.

공격에서 일반적인 공격은 트릭을 써서 사용자가 자신의 컴퓨터에 소프트웨어를 직접 설치하게 만드는 사회적 공격이다.

### 메타데이터와 감시

메타데이터는 데이터 자체는 아니고 데이터에 대한 데이터라고 할 수 있다.

### 인증과 권한부여

인증은 어떤 사람이나 대상이 실제로 그 사람이나 대상임을 증명하는 과정이다.

권한부여는 제대로 된 ‘자격증명’을 제공하지 않는 사람에게 접근을 제한한다는 것이다.

권한부여는 쉽지만, 인증은 어렵다.

## 크립토그래피

### 스테가노그래피

어떤 내용을 다른 내용 속에 감추는 방식으로 송신자와 수신자 사이에 연결의 자취가 남지 않기 때문에 비밀리에 통신하기 좋은 방법이다.

### 키 교환 문제

대칭 암호 시스템은 중간자 공격에 취약하다. 누가 중간에 키를 복사했는지 여부를 알 수없기 때문이다.

### 공개키암호

공개키 암호에서는 서로 연관된 키 쌍을 사용한다. 공개키 암호에서는 누구에 게나 알려져 있는 키인 공개키와 사용자만 알고 있어야 하는 키인 비밀키로 나뉘어져있다.

공개키 암호 시스템은 암호화와 복호화에 사용하는 키가 다르기 때문에 비대칭 암호 시스템이라고 할 수 있다.

공개키 암호는 트랩도어 함수에 의존하는데, 트랩도어 함수는 한 방향으로는 계산하기 쉽지만 비밀 정보를 알지 못하면 반대쪽 방향으로는 계산이 어려운 함수를 뜻한다.


### 전방향 안전성

전방향 안전성 암호화는 각 메시지마다 세션 키를 새로 만든다. 이런 방법을 통해 키를 알아내도 메시지를 단 하나만 풀 수 있게 된다.


### 암호학적 해시 함수

암호학적 해시 함수의 핵심 특성은 이들이 단방향함수라는 점이다. 단방향이라는 말은 입력에서 해시값을 만들어내기는 쉬워도 해시에서 입력을 만들어낼 수는 없거나 만들어내려면 비용이나 시간이 많이 들어서 비실용적이라는 뜻이다.


### 디지털 서명

디지털 서명을 통해 데이터가 진본임을 검증할 수 있는데 디지털 서명은 정합성, 부인방지, 인증을 제공한다. 

* 정합성 : 메시지가 변조됐는지 검증할 수 있다는 뜻
* 부인방지 : 비밀키로 메시지에 서명을 하기 때문에 보낸 사람이 자신이 서명했음을 부인하기가 어려움
* 인증 : 수신자가 받은 메시지가 원본과 같은 메시지라는 사실을 확인할 수 있음


### 공개키인프라

* 공개키 인프라스트럭처

이런 인프라에는 신뢰할 수 있는 제3자인 인증기관이 있어서 키가 어떤 당사자의 것임을 인증해준다.

인증기관이 키를 발행할 기관을 확실히 알고, 키가 그 기관의 키임을 인증하기 위해 인증기관의 키로 서명된 인증서를 발행한다.
