# 13장 컴퓨터 보안

정의한 안전함을 유지하기

## 보안과 프라이버시 개요

### 위협 모델

- 보안이 필요한 대상 목록과 각 보안 대상에 가해질 수 있는 공격 열거해서 이런 공격을 방어하는 방법을 설계하기

### 신뢰

- 신뢰의 대상 정하기
    - 의도적
    - 무능
    - 부정직

### 물리적 보안

- 공격 표면: 부수려고 하는 대상
- 백도어로 인해서 보안이 취약해짐

### 통신 보안

- 인증
- 크립토그래피

### 모던 타임즈

- DoS
- DDos
- 프록시 사용으로 추적 어려움
- 사회적 공격

### 메타데이터와 감시

- 메타데이터: 데이터에 대한 데이터
- 메타 데이터를 추적해서 정보 획득

### 사회적 맥락

- 도감청 문제
- DES

### 인증과 권한부여

- 인증: 어떤 사람이나 대상이 실제로 그 사람이나 대상임을 증명하는 과정
- 권한 부여: 제대로된 자격증명을 제공하지 않는 사람에게 접근 제한하는 것

## 크립토그래피

### 스테가노 그래피

- 어떤 내용을 다른 내용 속에 감추는 방식

### 치환 암호

- 원래 문자를 다른 문자로 바꿔서 암호화, 복호화

### 전치 암호

- 글자를 뒤섞는 암호 시스템

### 더 복잡한 암호

- 치환과 전치를 조합한 암호화 방식 등 더 복잡한 암호화 방식이 무한히 많이 있음

### 일회용 패드

- 양 사용자가 동기화돼야 함

### 키 교환 문제

- 대칭 암호시스템은 당사자가 같은 열쇠 사용해ㅑ함
- 중간에 가로채서 복사본 만들어도 알 방법 없음
- 즉, 중간자 공격에 취약

### 공개키 암호

- 공개키 암호는 지금까지 논의한 여러 문제 중 상당수를 해결해줌
- 연관된 키 쌍을 사용
- 공개키, 비밀키
- 배디칭 시스템
- 디피 헬먼 키 교환

### 전방향 안전성

- 대칭 암호 세션 키를 실제 통신에 사용하면, 키를 발견하면 모든 메시지를 읽을 수 있음
- 전방향 안정성 암호화: 각 메시지마다 새로 세션 키를 만듦

### 암호학적 해시 함수

- 단방향 함수
- MD5는 충돌 만들어 내는 방법이 발견됨

### 디지털 서명

- 데이터가 진본임을 검증할 수 있음
- 정합성
- 부인 방지
- 인증

### 공개키 인프라

- 은행 등이 공개 키 인프라스트럭처(PKI) 사용하고 있음
- 제3자 인증기관이 인증해줌

### 블록체인

- 크립토그래피를 응용한 또 다른 분야

### 패스워드 관리

- 패스워드를 암호화된 형태로 저장
- 패스워드 관리자를 사용

## 보안을 위한 소프트웨어 예방 조치

- 올바른 대상을 보호하라
- 로직은 세 번 체크하라
- 오류를 검사하라
- 공격 표면을 최소화하라
- 경계 내부에 머물러라
- 좋은 난수를 생성하기는 힘들다
- 네 코드를 알라
- 극단적 영리함은 여러분의 적이다
- 눈에 보이는 것을 이해하라
- 과다수집하지 마라
- 모아두지 마라
- 동적 메모리 할당은 여러분의 친구가 아니다
