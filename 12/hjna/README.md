# 병렬성과 비동기성 - 컴퓨터는 어떻게 한 번에 많은 일을 하는가


## 경합 조건이란 무엇인가?

* 경합 조건(race condition) : 두개 또는 그 이상의 프로그램이 같은 자원에 동시에 접근하고, 자원 사용 순서에 따라 결과가 달라지는 경우

## 공유 자원

대부분의 자원은 공유될 수 있다. 메모리는 항상 공유 문제와 연관이 되는데, 심지어는 공유 대상이 메모리가 아닌 경우에도 메모리가 관련된 경우가 많다.

## 프로세스와 스레드

프로세스는 사용자 공간에서 실행되는 프로그램이다. 멀티코어 시스템에서는 여러 프로그램이 병렬로 실행될 수 있다. 여기서, 병렬로 실행되는 프로그램이 자원을 공유해야 경합 조건이 발생한다.

여러 프로세스가 상당히 많은 데이터를 서로 공유해야하기 떄문에 액티비티 핸들러 개발은 까다로워졌다.

여기서 필요한 것은 핸들러를 인터럽트할 수 있게 만드는 것이다. 핸들러가 실행하는 중간에 잠시 실행을 중단하면서 상태를 저장하고 나중에 그 위치로 돌아와 실행을 재개하는 것이다.

상태는 스택에 저장된다. 

스레드는 정적인 데이터와 힙을 공유하지만 자체적으로 스택을 갖는 프로그램의 일부를 말한다.

한 스레드에서 다른 스레드로 실행이 넘어갈 때는 스레드 스케줄러가 CPU 레지스터를 저장해야 한다. 운영체제가 프로세스에서 다른 프로세스로 컨텍스트를 전환할 때 일어나는 일과 비슷하다. 스레드는 일반 프로세스보다 저장할 컨텍스트 크기가 훨씬 작기 때문에 프로세스 문맥 전환보다 스레드 문맥 전환이 더 빠르다. 이 때문에 스레드를 경량 프로세스라고도 한다.

스레드는 데이터를 공유하기 때문에, 보안문제가 발생할 수 있다.

탭에서 문제가 생기거나 버그가 발생하면 전체 프로세스가 멈춰버린다.

어떤 스레드가 작업을 완료하는 데 너무 오랜 시간이 걸리면 다른 모든 스레드가 실행되지 못해서 문제가 생길 수 있다.


## 락

우리가 처리해야 할 문제는 여러 작은 연산으로 이뤄진 작업을 어떻게 원자적으로 처리할지에 대한 것이다.

코드에서 중요한 부분을 상호 배제 메커니즘을 통해 원자적으로 처리하게 만들어야 한다. 이를 위한 개념인 어드바이저리 락이 있다. 이름이 이런 이유는 락을 지킬지 안 지킬지를 프로그램이 결정하기 때문이다.

## 트랜잭션과 작업 크기

성능을 향상할 가장 좋은 방법은 여러 연산을 한 트랜잭션에 담는 것이다. 트랜잭션에 들어 있는 모든 연산은 모두 다 성공하거나 모두 다 실패한다.

각 연산을 독립적으로 수행하는 대신 한꺼번에 묶어서 처리한다.

분명한 가이드라인은 어떤 대상을 잠그는 시간을 최소화하라는 것이다. 락이 걸려 있는 시간이 길면 동시성이 줄어들기 때문이다.

작업 크기라는 말은 락이 잠그고 있는 영역의 크기를 뜻한다.

### 락대기

프로그램이 락을 기다리는 동안 그 어떤 유용한 일도 할 수 없다면 락을 세밀하게 만들어도 아무 이득이 없다.

결국에는 ‘다중성’이라는 말을 멀티태스킹 전체 측면에서 살펴봐야 한다. 락을 기다리는 동안 수행할 유용한 작업이 없는 경우도 있다.

이런 작업의 복잡성은 규모를 쉽게 키우기 어렵게 만든다.

* 블로킹

시스템이 락을 할당할 수 있을 때까지 락을 요청한 프로그램을 일시중단하는 것.

* 논블로킹

프로그램이 계속 실행되고 나중에 락을 얻었는지 여부를 어떤 방식으로든 통지받게 되는 것.

### 교착상태

여러 프로세스 또는 스레드가 공유 자원을 기다리며 서로 진행하지 못하는 상황을 말한다.

* 교착상태가 발생하는 조건

1. 상호배제 :  공유 자원을 함께 쓸 수 없어서 어느 한 프로세스가 독점적으로 사용할 때
2. 점유대기 :  프로세스들은 어느 자원을 점유한 상태에서 다른 자원을 요청할 때
3. 비선점 :  프로세스가 할당받은 자원을 강제로 빼앗을 수 없을 때
4. 순환대기 : 각 프로세스가 서로 순환적으로 다른 프로세스가 갖고 있는 자원을 요구할 때

* 교착상태가 발생하지 않는 조건

1. 자원을 상호 배제하지 않고 언제든 공유할 수 있는 자원으로 만든다.
2. 어느 자원을 점유한 다음에 다른 자원을 요구하지 않고 한꺼번에 자원을 요구한다.
3. 선점형으로 바꾼다.(자원을 강제로 회수하거나 프로세스의 실행을 중단하고 다른 프로세스에 자원을 할당하는 방식)
4. 자원마다 우선순위를 부여해서 모든 프로세스가 다 서로 정해진 순서대로만 자원을 요구한다.

### 단기 락구현

여러 프로세서가 락에 사용하기 위한 '검사후설정' 이라는 명령어를 제공하는데, 이것은 원자적 명령어로 어떤 메모리 위치에 들어 있는 값을 1로 설정하고, 원래 그 위치에 들어 있던 값을 돌려준다.

둘 이상의 프로세스가 이 명령어를 사용하면 그중 한 프로세스의 검사 후 설정 명령어는 0을 반환하지만 나머지 프로세스의 검사 후 설정 명령어는 1을 반환한다.

락을 얻으려고 동시에 경합하는 프로세스가 아주 많을 때는 '비교 후 바꾸기' 라는 명령어가 있다. 한 값만 설정하는 대신 명령어를 호출하는 쪽에서 예전 값과 새 값을 모두 제공한다.  예전 값이 메모리 위치에 들어 있는 현재 값과 일치하면 메모리의 값을 새로운 값으로 바꾸고 프로세스는 락을 얻는다.

### 장기 락구현

장기간 락은 메모리보다 좀 더 영구적인 저장소에 저장된다. 이런 락은 파일을 사용해 구현되는 경우가 자주 있다.


## 브라우저 자바스크립트

자바스크립트 구현은 이벤트 루프를 통해 이루어진다. 여기서는 실행할 작업을 이벤트 큐에  추가한다. 자바스크립트는 이런 작업을 큐에서 한 번에 하나씩 꺼내서 실행하며 자바스크립트는 단일 스레드 프로그램이기 때문에 이런 작업은 인터럽트할 수가 없지만 프로그래머가 이벤트가 큐에 추가되는 순서를 제어할 수 있다.

원시 웹에서는 브라우저는 폼을 제출하고, 웹 페이지를 반환했다.

DOM으로 인해 기존 웹 페이지 전체를 바꾸는 대신, 웹 페이지 중 일부만 변경할 수 있게 됐다.

XHR은 기존의 페이지 로드 방식에서 벗어나 백그라운드에서 브라우저와 서버가 통신할 수 있게 해줬다.


## 비동기 함수와 프로미스

프로미스는 비동기 콜백 메커니즘을 언어 고유 기능으로 넣어서 라이브러리가 잘못 비동기 연산을 구현하지 못하게 한다.

프로미스는 비동기 작업의 완료 또는 실패를 처리하는 객체로서, 비동기 연산 결과를 .then(), .catch(), .finally() 로 처리할 수 있게 만들어주는 개념

여기서는 체이닝이 가능하다.

Promise로 만들어진 async와 await를 사용하여 동기식으로 작성해볼 수도 있다.

async 함수는 항상 Promise를 반환한다. 반환된 값은 자동으로 Promise로 감싸진다.

await 키워드는 Promise가 해결될 때까지 기다린다. await은 async 함수 안에서만 사용할 수 있다.
